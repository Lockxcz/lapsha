# LAPSHA v5 — тёмная тема, HOT, массовое редактирование и автоматические фото

Обновление подготовлено для текущего репозитория Lockxcz/lapsha, на основе коммита e1f9361. Установка — обычная замена файлов через GitHub. Установщиков, Python-команд и команд распаковки не требуется. Сайт и база в рабочем проекте этим архивом ещё не изменены.

## Что добавлено

- Тёмная основа по умолчанию и переключение на светлую. Выбор запоминается отдельно на каждом устройстве. На сайте переключатель находится в «Вид и обучение», в админке — под названием панели. Всего две темы.
- HOT / горячий: оранжевая метка, оформление карточки, фильтр в каталоге, индивидуальное и массовое редактирование. ICE, COLD, ALCO, NON ALCO и вариант без рамок сохранены.
- Массовое редактирование напитков текущей категории: выбор строк, выбор показанных, очистка выбора, подача, рамка, выравнивание, публикация/скрытие, перенос категории и подкатегории, замена/очистка тегов.
- Предпросмотр массовых изменений и списка затрагиваемых напитков. Можно скачать выбранные записи в JSON перед изменением. Экспорт — резервная копия, автоматического восстановления из неё нет.
- Автоматические фотографии для существующей алкогольной карты и новых напитков в ней. Ни искать картинки, ни выбирать результаты, ни загружать фото через админку не нужно.
- Поиск по каталогам Alcomag и New Elit Alco. Проверка настоящего названия на странице товара: сохраняются различия в выдержке, названии серии и годе вина. Объём бутылки и упаковка «in box» не мешают совпадению.
- Сохранение найденного файла в вашем Supabase Storage. Публичные карточки используют эту копию, а не постоянно загружают изображение магазина.
- Заполнение пустого краткого описания, вкуса и аромата короткими формулировками по найденным характеристикам. Заполненные вами тексты сохраняются. Если подходящих характеристик нет, текст не выдумывается.
- Очередь, повтор при недоступности источника, ежесуточное обновление каталога ссылок, защита от одновременного редактирования и сохранение источника каждой автоматической фотографии.
- Статусы рядом с напитками в админке и ссылка на исходную карточку магазина.
- Фотографии автоматически добавленных бутылок показываются целиком, без обрезки по высоте.

Сохранены новости со свайпом, поиск с лупой справа снизу, компактные/раскрывающиеся описания подкатегорий, избранное, сравнение, обучение меню, печать, настройки отображения и остальные функции v4. В этом обновлении нет замены ваших записей демонстрационными данными.

## 1. Supabase — один раз перед заменой файлов

1. Откройте **существующий** проект Supabase, который подключён к сайту.
2. SQL Editor → New query.
3. Откройте файл `supabase/update-v5.sql` из архива, скопируйте весь текст и выполните Run.
4. Дождитесь успешного выполнения. Скрипт уже включает изменения для HOT и предыдущие совместимые поля v3/v4. Отдельно выполнять старые обновления или `schema.sql` не нужно.
5. В Storage проверьте существующий публичный bucket `guide-media` — тот же, который использует админка. Если в вашем `assets/config.js` указано другое имя GUIDE_BUCKET, дальше задайте именно его.

SQL добавляет две служебные таблицы: `alcohol_catalog_cache` и `alcohol_photo_jobs`, функции и триггер очереди. Повторное выполнение допустимо. Существующие напитки, фотографии и описания не удаляются. Публичные посетители не имеют доступа к служебной очереди; доступ на чтение есть у авторизованных редакторов в рамках существующей модели админки.

## 2. Netlify — серверные настройки один раз

Откройте ваш сайт в Netlify → **Project configuration → Environment variables** и добавьте:

| Имя | Значение | Где взять |
|---|---|---|
| `SUPABASE_URL` | URL вашего текущего проекта Supabase | Тот же URL, что в `assets/config.js` |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный ключ текущего проекта | Supabase → Project Settings → API Keys: legacy `service_role` или новый secret key `sb_secret_…` |
| `GUIDE_BUCKET` | `guide-media`, либо ваше существующее имя bucket | Значение `window.GUIDE_BUCKET` в `assets/config.js` |

Задайте переменные для **Production** и области **Functions** (или All scopes, если разделения в вашем интерфейсе нет). `SUPABASE_SERVICE_ROLE_KEY` нельзя помещать в GitHub, `assets/config.js`, HTML или скриншоты. Публичный `anon` ключ для этой функции не подходит.

Никакой пароль администратора и никакой ключ стороннего ИИ не нужны. Новых магазинов в этом выпуске не добавлено: поддерживаются два изученных источника.

## 3. GitHub — загрузить и заменить

1. Сохраните резервную копию текущего репозитория: Code → Download ZIP.
2. Распакуйте `lapsha-v5-manual-update.zip` обычным файловым менеджером.
3. Откройте корень репозитория `Lockxcz/lapsha` → Add file → Upload files.
4. Перетащите **содержимое архива** в корень репозитория с сохранением папок: `assets`, `admpan`, `server`, `netlify`, `scripts`, `supabase`, `tests` и файлы рядом с ними. Не загружайте сам ZIP и не создавайте дополнительную внешнюю папку.
5. Подтвердите замену одноимённых файлов и сделайте Commit changes в ветку, из которой Netlify публикует сайт.

`assets/config.js` в архиве специально отсутствует — ваш текущий файл подключения должен остаться на месте. Старые файлы репозитория, которых нет в архиве, удалять не нужно.

Новые `package.json`, `package-lock.json`, `netlify.toml`, папки `scripts`, `server` и `netlify/functions` обязательны: именно они обеспечивают фоновую работу. Ничего вручную устанавливать на компьютере не требуется.

## 4. Передеплой Netlify

При подключении Netlify к GitHub коммит запускает публикацию автоматически. Если этого не произошло: Netlify → Deploys → Trigger deploy → Deploy site. Изменения переменных окружения требуют нового deploy.

В архиве `netlify.toml` задаёт:

- Base directory: корень репозитория.
- Build command: `npm run build`.
- Publish directory: `dist`.
- Node.js: 22.
- Functions directory: `netlify/functions`.

Netlify установит зависимости и соберёт публичные файлы. Серверные исходники, SQL и тесты в публичную папку сайта не копируются. Не оставляйте старую Publish directory `.` в ручных настройках, если она мешает конфигурации из репозитория.

После успешного **Production deploy** в разделе Functions должна появиться `alcohol-photo-sync` с расписанием каждые 2 минуты. Простая загрузка готовых HTML в Netlify Drop без сборки не запускает этот механизм.

## Когда появятся фотографии

Первые два успешных запуска заполняют каталоги ссылок. Затем обрабатывается одна позиция за запуск, каждые 2 минуты. Для примерно 90 пустых позиций первый проход займёт около трёх часов плюс время повторов. Уже заполненные фотографии пропускаются. Открывать сайт или админку для работы очереди не требуется.

Новые напитки попадают в очередь автоматически при сохранении в алкогольной карте. Поддерживаются slug `alcohol`, `alcohol-menu`, `alcohol-card` либо точные названия категории «Алкогольная карта», «Алкоголь», «Алкогольные напитки». В вашем текущем меню категория `alcohol` уже подходит. Кофе, лимонады, безалкогольные напитки и коктейльные разделы не обрабатываются.

Совпадение не гарантируется для каждой позиции. Если товара нет в этих магазинах, название слишком общее или в одной записи перечислены несколько вариантов, фотография остаётся пустой. Например, одну бутылку для «Martini Riserva (Ambrato / Rubino)» выбирать автоматически нельзя. Неподтверждённые позиции перепроверяются через 7 дней, сетевые ошибки — через час. Изменение названия снова ставит позицию в очередь.

Открытая страница каталога получает новые изображения после обновления страницы. В админке переключите категорию или перезагрузите страницу для обновления статуса. Заменённое вручную фото не перезаписывается.

## Если фото не появились

- Проверьте, что SQL выполнен именно в проекте, который указан в настройках Netlify.
- Проверьте наличие функции в опубликованном production deploy. Расписание не работает в обычном локальном предпросмотре и Deploy Preview.
- В логах `alcohol-photo-sync`: `catalogue-refreshed` означает загрузку каталога; `done` — фото добавлено; `unmatched` — нет точного совпадения; `retry` — будет повтор; `idle` — сейчас нет готовых задач.
- Ошибка `Database HTTP 401/403`: проверьте серверный ключ и его область Functions. `Database HTTP 404`: проверьте выполнение SQL. `Photo storage HTTP 400/404`: проверьте имя и наличие bucket.
- При недоступности магазина очередь ждёт следующего запуска; не подставляет случайную фотографию.
- Функция работает в пределах лимитов вашего тарифа Netlify/Supabase. Её можно отключить, убрав экспорт расписания из `netlify/functions/alcohol-photo-sync.mjs` и сделав новый deploy. Уже сохранённые фото останутся.

## Предпросмотр и проверка

`PREVIEW.html` можно открыть двойным щелчком: это автономный пример тёмного дизайна, переключения темы, HOT и функций каталога на демонстрационных записях. Он не подключается к вашей базе и не запускает автоподбор. Массовое редактирование находится в настоящей админке после обновления.

Проверены: сборка публичной папки, синтаксис JavaScript, 11 автоматических тестов парсинга, безопасности загрузок, точности сопоставления, очереди PostgreSQL и конфликтов с ручными изменениями. На живых страницах проверены фотографии и названия Bacardi Carta Blanca, Bulleit Bourbon, Glenmorangie Original 12 Years; для Alcomag проверено извлечение фотографии из Product-разметки вместо логотипа. Полный production-запуск возможен после ваших серверных настроек; запись в рабочую базу при подготовке не выполнялась.
