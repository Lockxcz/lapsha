# LAPSHA v8 — заметные уведомления и удобная админка

Обновление поверх **v7**. В текущем GitHub уже установлены файлы v7; v8 дополняет их. Нового SQL нет: меню, фото, цены, постоянный стоп-лист, тесты и вход по `admin` сохраняются.

## Установка без команд

1. Сохраните резервную копию текущего репозитория через GitHub → Code → Download ZIP.
2. Скачайте и распакуйте `lapsha-v8-manual-update.zip` обычным проводником.
3. GitHub → репозиторий Lockxcz/lapsha → Add file → Upload files. Загрузите содержимое архива **в корень**, сохраняя папки `assets`, `admpan`, `tests`. Замените одноимённые файлы и сделайте commit. Не создавайте дополнительную вложенную папку.
4. Дождитесь успешного deploy Netlify. Настройки прежние: `npm run build`, каталог `dist`, Node.js 22+. Если автоматическое развёртывание отключено, запустите deploy последнего commit в Netlify.
5. Обновите страницы на телефоне и POS. Если видите старый интерфейс, обновите без кэша на компьютере; на телефоне закройте и откройте страницу.

`assets/config.js`, адрес проекта Supabase, аккаунты и пароли не меняйте. SQL v7 повторять для v8 не требуется. Если v7 ещё не установлен в базе и тесты/стоп-лист не работают, сначала установите v7 по его инструкции. Не удаляйте остальные файлы репозитория: это архив обновления, а не пустой новый сайт.

## Как теперь выглядят уведомления

Новое событие стоп-листа или сообщение смены открывает крупную карточку снизу вверх. В ней — название, текст, важность, обратный отсчёт, полоса оставшегося времени и кнопки **«Подтвердить»** / **«Все события»**. Срочные сообщения и постановка в стоп выделяются красным акцентом. Длинный текст можно прокрутить внутри карточки.

Карточка исчезает при подтверждении либо через **60 секунд**. Если за одно обновление пришли несколько событий, они объединяются в одну карточку с перечислением. Следующие обновления встают в очередь: каждое получает свою минуту после показа и не заменяет предыдущее.

**Исчезновение по таймеру не означает прочтение.** Такие события остаются непрочитанными в ленте. «Подтвердить» отмечает показанные события прочитанными на этом устройстве. «Все события» открывает ленту, где можно прочитать отдельное событие или отметить всё. Общей ведомости «какой официант подтвердил» пока нет.

Официант может открыть шестерёнку → «Проверить уведомление». Это локальная демонстрация: она не публикует новость и не меняет меню. Звук включается отдельным переключателем после взаимодействия с браузером; в новой сессии его нужно включить снова.

Минутный таймер относится к уведомлениям **внутри сайта**. Продолжительность системного уведомления Windows задаёт ОС. Закрытый браузер уведомления не получает; показ поверх r_keeper этой версией не добавляется. В фоновых вкладках браузер может замедлять таймеры; при возвращении истёкшая карточка убирается. Для открытых карточек и диалогов уведомление размещается в активном диалоге; для отображения поверх него используются возможности современного браузера.

## Управление сменой — `/admpan/pos.html`

- На телефоне — нижние вкладки: стоп-лист, сообщения, журнал, настройки.
- На компьютере — широкая навигация, просторные фильтры и компактный режим списка.
- Верхняя сводка показывает количество стопов, активных сообщений и сегодняшнюю дату.
- Стоп можно включить/снять переключателем. Он открывает проверку действия; запись меняется только после сохранения.
- Выбранные для массовой операции напитки перечислены по именам. Можно показать только выбранные и сбросить фильтры.
- Поиск находит название, подкатегорию и причину стопа.
- Стоп-лист можно скопировать целиком, скачать CSV или напечатать.
- Строка состояния показывает время последней проверки и результат сохранения. Без актуального соединения кнопки записи заблокированы.

Стопы по-прежнему сохраняются на следующий день до ручного снятия. Дата постановки не сбрасывается при правке причины. Количества и «Мало в наличии» не возвращаются.

## Сообщения — меньше повторного ввода

Текст, заголовок, важность, срок и закрепление автоматически сохраняются **локально на этом устройстве для текущего администратора**. Пароли в черновик не записываются. При возвращении в панель можно продолжить работу.

При выборе шаблона, копировании сообщения или создании нового черновика предыдущий текст доступен через «Вернуть предыдущий черновик». Хранится текущий и один предыдущий вариант; это не облачная история версий.

Можно искать сообщения, показывать активные либо снятые/истёкшие, редактировать существующее, скопировать его в новый черновик или снять с публикации. Для редактирования можно сохранить прежний срок либо назначить новый.

Перед отправкой открывается отдельная проверка текста, важности, закрепления и срока. Кнопка **«Посмотреть уведомление»** показывает локальный пример карточки с вашим текстом. Только **«Подтвердить публикацию»** записывает сообщение на сайт. Ctrl/⌘ + Enter открывает проверку из формы сообщения.

При изменении другим редактором сохранение отклоняется: откройте свежую версию из списка. Новая публикация получает постоянный идентификатор черновика, чтобы повторная попытка после сетевого сбоя не создавала вторую такую же запись. При неясном результате сначала проверьте список сообщений.

## Полный редактор меню — `/admpan/`

Увеличены поля, кнопки и подписи. На мобильном экранная боковая навигация заменена выпадающим выбором раздела, добавлены быстрые переходы в управление сменой и тесты, а также кнопка выхода. В модальных редакторах кнопки сохранения удерживаются у нижней границы при прокрутке. Таблицы прокручиваются горизонтально внутри блока.

Публикация карточек и категорий оформлена переключателями. Добавлена возможность показать пароль при входе. Старые операции редактирования, импорта и массовой обработки сохраняются.

## Проверка после установки

1. В управлении сменой откройте сообщения. Введите тестовый текст, перезагрузите страницу — черновик должен восстановиться.
2. Откройте проверку публикации и нажмите «Посмотреть уведомление». Подтвердите локальный пример; он не должен появиться у официантов.
3. Опубликуйте тестовое сообщение. На втором устройстве проверьте появление снизу, таймер и подтверждение. Для автоматического исчезновения повторите с другим сообщением и подождите минуту.
4. Снимите тестовые сообщения с публикации. Проверьте одну постановку и снятие стопа, сохранив фактическое наличие.
5. На телефоне проверьте нижние вкладки и выбор раздела полного редактора.

В разработке прошёл 21 автоматический тест, включая минутный таймер, очередь, защиту следующего уведомления от запоздалого нажатия, миграцию v7, стоп-лист, тесты меню и фотоимпорт. Проверены сборка, синтаксис скриптов и ссылки. На вашем физическом POS и в вашем браузере визуальная проверка не выполнялась; v8 на ваш Netlify не публиковался.
