# LAPSHA v4 — новый дизайн и 30 функций

Обновление подготовлено на основе установленной v3 в GitHub Lockxcz/lapsha, коммит 55f56b8.

## Что изменилось в дизайне

Светлая основа, графитовый текст, красные акценты, новые пропорции шапки, крупные фотографии напитков, единая сетка и компактная навигация. Новости оформлены как отдельные карточки; закреплённые выделены бордовым фоном. Вместо большого вступления — короткая шапка и раскрываемый блок «О гиде».

Сохранены предыдущие функции: новости со свайпом, быстрый поиск, избранное, цветные рамки, фотографии, подробности напитков, импорт, настройки и авторизация. Ваши записи не заменяются демонстрационными.

Тема, вид, избранное, изученные напитки, недавно открытые и прочитанные новости сохраняются только в текущем браузере. На другой телефон они не переносятся и никому не отправляются. Очистка данных браузера удаляет эти отметки.

Сравнение и обучение используют только заполненные данные. Отсутствующие характеристики отмечаются как «Не указано». Это не ИИ-генерация.

## Установка — только ручная замена файлов

Терминал, установщик, unzip и Python не нужны.

### 1. Подготовка

В GitHub скачайте текущий проект через Code → Download ZIP как резервную копию. Распакуйте lapsha-v4-manual-update.zip на телефоне или компьютере.

Архив обновления содержит файлы прямо в корне: index.html, папки assets, admpan, supabase, этот README и PREVIEW.html. Отдельной папки files и установщика нет.

### 2. Supabase — сначала добавьте поля

1. Откройте ваш текущий проект Supabase.
2. SQL Editor → New query.
3. Откройте supabase/update-v4.sql из архива и скопируйте весь текст.
4. Вставьте его в SQL Editor → Run. Дождитесь успешного выполнения.

Скрипт добавляет поля v4 и, если необходимо, совместимые поля v3. Его можно выполнить повторно. Он не удаляет данные, не меняет пароли, ключи, политики доступа и фотографии. Не запускайте заново исходный schema.sql на существующей базе.

Если SQL сообщает, что таблицы не существуют, проверьте выбранный проект. Новое обновление рассчитано на существующую базу этого гида.

### 3. GitHub — замените файлы

В репозитории Lockxcz/lapsha откройте ветку, с которой связан Netlify (обычно main).

Файлы в корне архива загружайте в корень репозитория; содержимое assets — в существующую assets; содержимое admpan — в существующую admpan; update-v4.sql — в supabase. Через GitHub можно использовать Add file → Upload files, затем Commit changes. Через веб-редактор можно загрузить и заменить файлы в панели проекта.

Папки объединяйте, а не удаляйте целиком. В архиве специально нет assets/config.js: ваш файл с подключением к Supabase остаётся на месте. Также остаются существующие style.css, icons.js, admin.css и другие файлы, не входящие в обновление. Старые v2/v3 стили используются как основа.

Лучше загрузить весь комплект одним коммитом, чтобы Netlify не опубликовал промежуточную версию без части файлов.

PREVIEW.html и README-V4.md не обязательны для работы меню. PREVIEW.html — автономная демонстрация дизайна и инструментов с примерами данных; фотографии двух кофейных напитков взяты из вашего публичного гида. Пример не сохраняет демонстрационные данные в Supabase.

### 4. Netlify

После коммита в подключённую ветку дождитесь нового деплоя в Deploys и статуса Published. Если автообновление отключено, запустите повторный деплой из Netlify.

Настройки текущего проекта сохраняются: статические HTML/CSS/JS, Publish directory — точка (.), Build command не нужен. Новый репозиторий, новый сайт, npm и новые переменные окружения не требуются.

### 5. Первое открытие

1. Обновите страницу сайта и /admpan/; при старом дизайне проверьте в новой приватной вкладке.
2. Описания категорий теперь по умолчанию раскрываются по нажатию. Для другого вида: Категории → Изменить → Описание под названием.
3. Вкладка «Подкатегории» позволяет управлять группами. Чтобы отнести напиток в группу: Напитки → Изменить → Категория и Группа.
4. В меню «Вид и обучение» выберите удобную тему и размер текста.
5. После редактирования контента сохраните изменения и обновите открытую публичную страницу. Автоматическая синхронизация уже открытых вкладок в этой версии не добавлялась.

## Если нужно вернуть v3

Восстановите заменённые файлы из резервного ZIP или отмените коммит обновления в GitHub. Если после v4 были другие изменения, учитывайте их при восстановлении. Новые SQL-поля можно оставить: v3 их игнорирует. Не удаляйте таблицы и не импортируйте меню заново.

## Проверка и ограничения

Проверены синтаксис JavaScript, связи HTML с локальными файлами, отсутствие повторяющихся ID и сценарии в DOM-среде на тестовых данных: описания, фильтры, избранное, сравнение, изучение, новости, подкатегории, мобильные размеры предпросмотра и состав запросов сохранения.

SQL подготовлен по схеме вашего репозитория; на рабочей Supabase не выполнялся. Изменения в действующий GitHub/Netlify не отправлялись. Визуальная проверка в полноценном браузере и тест реального сохранения в вашу базу в этой сессии не проводились.
