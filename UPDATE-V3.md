# LAPSHA · обновление v3

Подготовлено для Lockxcz/lapsha, исходный коммит 4bb593c429f77c94ea84da60679217092251eec6.

## Что изменилось

1. Прошлые v2-файлы не были подключены к страницам. Новые функции теперь встроены в основные страницы без запуска двух конкурирующих лент новостей.
2. Новости — широкие карточки, увеличенный текст, горизонтальный свайп на телефоне.
3. Перетаскивание мышью, стрелки, управление с клавиатуры и счётчик позиции.
4. Заголовок новости, переносы строк и закрепление важных новостей перед обычными. Порядок внутри каждой группы задаётся полем «Порядок».
5. Описание категории сразу под названием, например «Кофе».
6. Выравнивание категории, карточки напитка и новости: слева, по центру или справа.
7. Живой предпросмотр категории, напитка и новости прямо при редактировании. Используются те же функции отрисовки, что на сайте; показываются текущие поля, включая несохранённые.
8. Выбор рамки вокруг фото и текста: ALCO — красная, NON ALCO — синяя, по тегам или без цветной рамки и меток.
9. Отдельная подача ICE / COLD с голубой меткой. ALCO + ICE сохраняет красную рамку и обе метки. В режиме «Без цветной рамки и меток» метки тоже скрываются.
10. Круглая лупа справа снизу: поиск по напиткам, категориям, вкусу и составу. Нажатие на результат раскрывает подробности и прокручивает к карточке.
11. Поиск понимает несколько слов, ё/е и регистр. Поиск в шапке учитывает название категории и группы.
12. Переход из быстрого поиска сбрасывает старые фильтры, чтобы найденная карточка была видна. В выдаче до 100 результатов; при большем количестве предлагается уточнить запрос.
13. Избранное и фильтр избранного. Хранится только в браузере этого устройства; не синхронизируется между телефонами.
14. Кнопки «Раскрыть подробности» и «Свернуть подробности» для изучения меню.
15. Копирование напитка в новый неопубликованный черновик. Создание происходит только после «Сохранить».
16. Более удобные мобильные формы: крупные поля, переносы, прокручиваемые таблицы, доступные кнопки сохранения.
17. Включена браузерная проверка орфографии в описаниях. Её работа зависит от браузера и языка клавиатуры; текст автоматически не переписывается.
18. Исправлены пропадание напитка с чужой/устаревшей группой и отсутствие подробностей, если заполнено только «Сочетание».
19. Текст карточек безопасно выводится как текст; в главном заголовке сохранён разрешённый <em>курсив</em>.
20. Автономный PREVIEW.html на демонстрационных данных. Откройте его в браузере, чтобы попробовать ленту, поиск и избранное. Это не выгрузка вашей базы.

## Установка с телефона через GitHub Codespaces

Сначала Supabase, затем файлы сайта. Не запускайте старые apply-update.py / apply-update.bat для этого обновления.

### 1. Supabase

1. Откройте ваш текущий проект Supabase.
2. SQL Editor → New query.
3. Из архива откройте files/supabase/update-v3.sql, скопируйте весь текст в редактор и нажмите Run.
4. Дождитесь успешного выполнения. Скрипт можно повторить: он добавляет только отсутствующие поля. Напитки, фото, категории, новости, авторизация и политики доступа не удаляются и не заменяются.
5. Не запускайте заново supabase/schema.sql на существующей базе. Для новой пустой базы нужен сначала schema.sql из вашего репозитория, потом update-v3.sql.
6. Не нужны новые ключи, Storage buckets или Edge Functions. assets/config.js остаётся вашим.

Если видите «relation does not exist», проверьте, тот ли проект открыт. Если нет прав, выполняйте запрос от владельца проекта. SQL подготовлен по схеме репозитория; на вашей работающей базе он в этой сессии не запускался.

### 2. GitHub

1. Откройте https://github.com/Lockxcz/lapsha.
2. Code → Codespaces → создайте или откройте Codespace на main. github.dev по нажатию точки — только редактор, нужного терминала там нет.
3. Откройте Terminal → New Terminal. Убедитесь, что терминал находится в корне lapsha, рядом с index.html и assets.
4. Если в Codespace есть ваши несохранённые изменения, сначала сохраните их отдельно или закоммитьте. Обновите ветку:

```bash
git switch main
git pull --ff-only
```

5. Загрузите lapsha-v3-update.zip в корень проекта через панель файлов Codespaces (Upload).
6. Распакуйте обновление во временную папку и запустите установщик:

```bash
unzip -o lapsha-v3-update.zip -d /tmp/lapsha-v3-update
python3 /tmp/lapsha-v3-update/install-v3.py
```

Установщик проверяет каждую замену по исходному содержимому и делает резервную копию вне репозитория. Если ваши файлы уже отличаются от изученной версии, он остановится ДО замены и покажет список. Не заменяйте такие файлы вслепую — требуется перенести изменения в текущую версию. Повторная установка той же версии допустима.

7. Посмотрите изменения и отправьте только файлы обновления:

```bash
git diff --stat
git add index.html assets/app.js assets/guide-ui.js assets/guide-extras.js assets/guide-v3.css admpan/index.html admpan/admin.js admpan/admin-v3.css supabase/update-v3.sql PREVIEW.html UPDATE-V3.md
git commit -m "Update guide v3: news, search, previews and drink frames"
git push origin main
```

Архив zip и старые установщики добавлять в коммит не нужно. assets/lapsha-update-v2.css используется существующий, его удалять нельзя. Старые v2 JS-файлы не подключаются и не мешают.

### 3. Netlify

Если текущий сайт связан с Lockxcz/lapsha и веткой main, push запустит новый деплой. Откройте Deploys и дождитесь Published. Это стандартное поведение непрерывного деплоя Netlify: https://docs.netlify.com/deploy/create-deploys/.

У проекта статические HTML/CSS/JS, npm-сборка не нужна. Текущий netlify.toml уже содержит publish = ".". В настройках Build & deploy:

- Production branch: main.
- Base directory: корень репозитория (пусто).
- Build command: пусто.
- Publish directory: .

Если деплой не стартовал, проверьте подключение репозитория, ветку и что сборки не остановлены. Затем запустите повторный деплой в Deploys. Настройки: https://docs.netlify.com/build/configure-builds/overview/.

### 4. Проверка после публикации

1. Откройте сайт и /admpan/ в новой вкладке; если видна старая версия — обновите страницу или проверьте в приватной вкладке.
2. Категории → Изменить → заполните описание, выберите выравнивание, проверьте предпросмотр, сохраните.
3. Напитки → Изменить → выберите рамку и подачу. Никакие классификации по названию напитка не угадываются: используется ваш выбор или существующие теги.
4. Новости → Добавить → заполните заголовок и текст. Создайте несколько новостей, чтобы проверить свайп. «Показывать на сайте» должно быть включено.
5. Обновите публичную страницу после сохранения. Автоматическая синхронизация уже открытой вкладки в этом обновлении не добавлялась.
6. Проверьте поиск при активном фильтре, избранное, фото и подробности.

## Как откатить файлы

Если обновление ещё не закоммичено, резервная копия по пути, который напечатал установщик, содержит предыдущие версии изменённых файлов. Если уже отправлено в GitHub, найдите коммит обновления:

```bash
git log --oneline -5
```

Затем выполните git revert с хешем именно этого коммита и git push origin main. Это создаст обратный коммит без стирания истории. Если после обновления были другие правки, возможны конфликты — не используйте reset --hard. Добавленные SQL-поля можно оставить: старая версия сайта их просто игнорирует. Меню из базы не нужно удалять или импортировать заново.
