# LAPSHA v6 — рабочее меню для POS

Обновление существующей версии v5. Главная страница становится экраном официанта; полный старый гид остаётся по адресу `/guide.html`. Меню, фотографии, импорт алкоголя и прежняя админка сохраняются. Новый экран управления сменой: `/admpan/pos.html`.

## Установка без команд и установщиков

1. Скачайте текущий репозиторий GitHub через **Code → Download ZIP** как резервную копию. Сохраните свой `assets/config.js`.
2. В существующем проекте Supabase откройте **SQL Editor → New query**. Вставьте целиком содержимое `supabase/update-v6.sql` из архива и нажмите **Run**. Дождитесь успешного выполнения. Это дополнение к установленной v5: не запускайте заново исходную схему и импорт меню. SQL можно выполнить повторно; он не заменяет названия, цены и фото.
3. Распакуйте архив обычным проводником. В GitHub откройте свой репозиторий → **Add file → Upload files**. Загрузите содержимое архива в корень, сохраняя папки `assets`, `admpan`, `scripts`, `supabase`, `tests`. Замените одноимённые файлы и сделайте commit. Не создавайте дополнительную вложенную папку. `assets/config.js` в архиве отсутствует: ваш существующий файл должен остаться.
4. В подключённом Netlify дождитесь нового успешного deploy. Сборка остаётся `npm run build`, папка публикации — `dist`, Node.js — 22 или новее. Старые переменные окружения и функции автоматического подбора фотографий сохраняются. Если автоматический deploy выключен, запустите deploy последнего commit через раздел Deploys.
5. Откройте `/admpan/pos.html`, войдите существующим аккаунтом администратора. Выставьте фактический стоп-лист: изначально позиции без записи наличия считаются доступными. Проверьте результат на главной странице второго терминала.
6. На POS обновите страницу. В шестерёнке выберите тему, размер карточек и место терминала. Включите звук, если нужен; разрешите системные уведомления отдельной кнопкой. Кнопка «На весь экран» включает полноэкранный режим браузера.

Никакие `unzip`, Python, установщики или локальная сборка пользователю не нужны. Архив содержит только файлы обновления: не удаляйте остальные файлы репозитория.

## Как пользоваться

**Официант:** коснитесь поиска → введите часть названия → откройте карточку. Красный СТОП означает недоступность; «Мало» требует внимания. При потере связи метки становятся серыми с подписью «уточнить». События и отметки прочтения доступны по кнопке сверху.

**Администратор:** откройте управление сменой → найдите напиток → СТОП / Мало / В наличии → сохраните. Для группы отметьте позиции и выберите действие над списком. В окне видны названия всех выбранных позиций. Максимум — 200 за одну операцию. Если статус уже поменял другой редактор, закройте окно, проверьте свежие значения и повторите выбор: автоматической перезаписи нет.

**Сообщение:** вкладка «Сообщения смены» → шаблон или свой текст → срок и важность → проверьте предпросмотр → опубликуйте. При неясном сетевом результате сначала обновите список, прежде чем повторять публикацию.

## Синхронизация и практические ограничения

SQL подключает таблицу `pos_revision` к существующей публикации `supabase_realtime`. При активном Realtime изменение вызывает обновление экрана; дополнительно версия проверяется примерно каждые 10 секунд в активной вкладке и 30 секунд в фоновой. Браузер может замедлять фоновые вкладки. После возвращения в окно и восстановления сети запускается обновление. Это не обещание нулевой задержки. [Настройка Supabase Realtime](https://supabase.com/docs/guides/realtime/postgres-changes).

Внутренние уведомления работают в открытом сайте. Системные требуют разрешения браузера и ОС; показ поверх других программ зависит от их настроек. При закрытом браузере эта версия уведомления не доставляет. Поверх эксклюзивного полноэкранного r_keeper показ не гарантируется. [О браузерных уведомлениях](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API).

Это информационный помощник, без интеграции продаж и заказов с кассой. Остатки задаются вручную; продажи не уменьшают их автоматически. Ожидаемый срок — подсказка: напиток не возвращается в наличие автоматически. Сохранённые данные помогают при потере связи в открытой странице, но это не полноценное автономное приложение с гарантированным запуском без интернета.

Используется существующая модель доступа v5: вошедшие пользователи Supabase являются редакторами. Отдельных ролей кассира/официанта/управляющего новая версия не создаёт. Посетители читают опубликованное меню и сообщения; не размещайте в них конфиденциальные сведения.

## Проверка после установки

На двух устройствах откройте сайт. Поставьте одну реальную тестовую позицию в стоп, убедитесь, что второй экран обновился, затем верните правильный статус. Опубликуйте тестовое сообщение и снимите его. На одном устройстве отключите сеть: появится предупреждение; после восстановления свежие значения загрузятся автоматически. Проверьте клавиатуру и размеры кнопок на вашем разрешении POS.

В разработке прошли 13 автоматических тестов, включая миграцию PostgreSQL, права доступа, повторный запуск SQL, отмену конфликтной массовой операции и потерю связи. Дополнительно проверены ввод экранной клавиатурой и отправка стопа через интерфейс в DOM-среде. Сборка и синтаксис JavaScript проверены. На вашем Netlify, Supabase и физическом POS обновление ещё не устанавливалось; визуальная проверка на вашем терминале остаётся после установки.

## Откат

Верните предыдущие версии изменённых файлов через GitHub и дождитесь deploy. Для быстрого возвращения старой главной страницы можно скопировать содержимое `guide.html` в `index.html`. Новые таблицы можно оставить: существующие данные меню не требуют обратного импорта. Не удаляйте таблицы или проект Supabase для отката интерфейса.
