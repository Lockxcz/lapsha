# LAPSHA v7 — меню, стоп-лист и обучение

Обновление для установленной v5 или v6. Файлы подготовлены на основе репозитория Lockxcz/lapsha и предыдущего POS-обновления. Содержимое меню, фотографии и цены не переимпортируются.

## Установка обычной заменой файлов

1. Сохраните текущий репозиторий через GitHub → Code → Download ZIP. Не удаляйте существующие файлы сайта.
2. Распакуйте `lapsha-v7-manual-update.zip` обычным проводником.
3. В существующем проекте Supabase откройте SQL Editor. Скопируйте **весь** файл `supabase/update-v7.sql` из архива и выполните его. Он включает основу POS v6 и дополнения v7; отдельно выполнять v6 не нужно. Дождитесь успешного завершения. Скрипт повторяемый и выполняется в одной транзакции.
4. GitHub → ваш репозиторий → Add file → Upload files. Загрузите содержимое архива в корень, сохраняя структуру папок, замените одноимённые файлы и сделайте commit. Не загружайте всё внутрь дополнительной папки `lapsha-v7`.
5. Дождитесь успешного deploy Netlify. Настройки прежние: `npm run build`, публикация `dist`, Node.js 22+. Новых переменных Netlify и платных сервисов не требуется.
6. Обновите страницы на терминалах. На компьютере при старом оформлении используйте обновление без кэша, на телефоне закройте и снова откройте страницу.

**Существующий `assets/config.js` сохраняется.** Его нет в архиве. Не заменяйте проект Supabase и не запускайте повторный импорт меню. После установки v7 не запускайте старый `update-v6.sql`: используйте именно объединённый файл v7.

Ссылки после установки:

- Официант: главная страница сайта.
- Управление стоп-листом и сообщениями: `/admpan/pos.html`.
- Тесты для команды: `/training.html`.
- Создание собственных вопросов: `/admpan/tests.html`.
- Полный редактор меню: `/admpan/`.
- Учебный гид прежней версии: `/guide.html`.

## Вход просто по admin

В поле логина вводите **admin**, затем **свой прежний пароль**. Это сокращение для существующего аккаунта `admin@gmail.com`, а не новый аккаунт и не новый пароль. Вход по полному email тоже остаётся доступным.

Если ваш действующий аккаунт использует ДРУГОЙ email, один раз откройте в GitHub `assets/login-alias.js` и замените `admin@gmail.com` на его адрес. После deploy логин `admin` будет входить в него. Пароль в этот файл писать нельзя. Адрес аккаунта и его пароль в Supabase менять не нужно.

Сокращённый вход работает в полном редакторе, управлении сменой и импорте фото. Редактор тестов использует тот же вход: сначала авторизуйтесь в управлении сменой, затем откройте тесты.

## Стоп-лист без остатков

Теперь есть только **«В наличии»** и **«СТОП»**. Никаких количеств, малого остатка и ожидаемого времени возврата в новом интерфейсе.

Чтобы добавить: найдите существующую позицию → СТОП → выберите причину → Сохранить. Чтобы убрать: В наличии → Сохранить. Несколько позиций можно выбрать и обработать вместе. Новые напитки сначала добавляются в обычном редакторе меню, затем доступны в стоп-листе.

Дата и время постановки фиксируются автоматически. На следующий день запись остаётся. Изменение причины не переносит исходную дату постановки. После снятия и новой постановки начинается новая дата. Даты отображаются по часовому поясу устройства: проверьте правильность времени на POS.

Существующие записи СТОП сохраняются. При первой установке v7 для старых записей дата берётся из последнего изменения v6, потому что отдельной даты постановки тогда не было. Бывшие записи «Мало в наличии» становятся «В наличии» — они не считались стопами; при необходимости поставьте их в стоп вручную. Старые количества больше не используются.

Скачивание CSV и печать показывают стоп-лист с причинами и датами. При конфликте двух редакторов операция отклоняется целиком: обновите данные и проверьте значения. При потере связи сохранение блокируется.

## Тесты с четырьмя вариантами

Откройте «Тесты» → раздел → 5, 10 или 20 вопросов → режим → Начать.

- **Обучение:** правильный ответ и пояснение сразу.
- **Проверка:** ответы разбираются после завершения.
- Варианты и вопросы перемешиваются.
- Есть шкала прохождения, результат в процентах, разбор каждого вопроса и повтор ошибок.
- Можно сохранить незавершённую тренировку и продолжить на этом же устройстве. Продолжение использует сохранённую версию вопросов; новая тренировка после перезагрузки получает свежие данные.
- История последних 30 тренировок хранится локально; в интерфейсе показаны последние восемь. Общей ведомости сотрудников эта версия не создаёт.
- На компьютере цифры 1–4 выбирают ответ, Enter переходит дальше после выбора.

Автоматические вопросы составляются из опубликованных полей **состав, страна, вкус, аромат и сочетание с едой**. Ответы берутся из ваших карточек, без ИИ и внешних API. Внутри категории должны быть как минимум четыре различных подходящих значения. Если данных недостаточно, вопрос пропускается: выдуманные ответы не добавляются. Повторяющиеся названия напитков исключаются из автоматических вопросов, чтобы не задавать двусмысленный вопрос.

Для собственного вопроса откройте редактор тестов: раздел, вопрос, четыре варианта, номер правильного ответа, пояснение, черновик или публикация. Варианты должны отличаться. Можно редактировать, копировать вопрос в новый черновик и искать по тексту. Чтобы убрать вопрос из новых тренировок, сохраните его как черновик. Изменения появятся после новой загрузки раздела тестов.

Это открытая самопроверка по меню, а не защищённый экзамен: правильные ответы доступны приложению. Для обучения командой ссылку можно открыть на телефоне, POS и компьютере без отдельного аккаунта официанта.

## Проверка и ограничения

Автоматические проверки: миграция, повторная установка, сохранение стопа с прошлой датой, права доступа, конфликтная массовая операция, проверка вариантов теста, отсеивание черновиков, перемешивание с сохранением правильного ответа и сокращение логина. Сборка, синтаксис новых скриптов и локальные ссылки проверены. Визуальная проверка на вашем физическом терминале и установка в вашу базу ещё не выполнялись.

Перед работой смены проверьте на двух устройствах одну постановку и снятие стопа, новость, вход admin и тренировку. В новом рабочем интерфейсе ориентируйтесь на подтверждение связи. Realtime и резервный опрос сохраняются из v6; мгновенность зависит от сети и фоновых ограничений браузера. Системные уведомления требуют открытого сайта и разрешения ОС; интеграции с r_keeper и показов поверх него эта версия не добавляет.

Модель доступа прежняя: авторизованные аккаунты Supabase — редакторы, а опубликованные материалы видны посетителям. Фото и тексты меню остаются вашими текущими; обновление не меняет их содержимое. При откате верните предыдущие файлы через GitHub. Удалять базу, фотографии или новые таблицы для отката интерфейса не нужно; прежние значения «Мало» автоматически обратно не восстанавливаются.
